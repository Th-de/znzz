# 流程改动 · 程序修改计划

依据桌面《流程改动.doc》。目标：一单一品、工厂做完全部工序、工序不再拆数量；分期按期生成工单；先付质检费再质检；按五类质检结论分支处理；关闭本阶段则取消该厂后续期并按「当前+后续工费 5%」赔买家。

现状差距（已实现 vs 文档）：现网仍是「按工序拆数量 + 按工序拆工单」；质检无单价、交货后直接质检；关闭本段不赔、不取消后续工单；让步赔付已按 \(A\times(m-Y)\) 与良率带宽，但与文档「数量不齐让步扣本阶段全部工费 5%」不一致。

---

## 阶段 0 · 口径冻结（改代码前）

1. 订单粒度：一个需求一种零件；一个工厂对该需求的「一期」= 一张阶段订单（不是一道工序一张单）。
2. 工序：只描述工艺路线，数量一律等于该厂该期承接件数。
3. 分期：发布时每期必须有交付时间；未到时间区间不能上报、不能交付。
4. 质检费：标价元/件；首次买家按实交件数付，付完才检；质量返工工厂付（件数仍为原约定）；数量返工剩余件买家付；入账运营账户。
5. 关闭连锁：扣该厂「当前期 + 后续期」工费合计的 5% 赔买家，并关闭该厂该需求后续订单。

---

## 阶段 1 · 数据模型

| 项 | 改动 |
|---|---|
| `demand_process` | 去掉「工序数量必须加总=总需求」校验；工序无独立数量，或数量冗余等于需求数量 |
| `work_stage` | 从「按工序拆」改为「按工厂 + 交付期拆」。字段建议：`demand_id`、`period_no`、`period_start/end`、`agreed_qty`、`delivered_qty`、`inspect_fee_status/amount`、`parent_stage_id`（返工单）、`rework_kind`（QUALITY/QTY） |
| 质检价目 | 需求上增加检验方式单价（FAI/AQL/全检 元/件），或独立 `inspect_price` |
| 资金流水 | 增加类型 `INSPECT_FEE`，收款方运营/平台账户 |
| 报价 | 工厂报的是「该品全部工序、承接件数、单价」，不再按工序分别报数量 |

兼容：旧数据要么迁移脚本把同厂多工序工单合并为期次订单，要么仅新需求走新模型（推荐后者，避免演示库硬迁）。

## 阶段 2 · 发布与报名（buyer/factory + Demand/Bidding）

前端 `Publish.vue`：

- 「质量门槛」与工序列表合并；工序行去掉数量，只留工序名与要求。
- 检验方式选项旁标明单价（元/件）；保存 `inspectPrice`。
- 分期：每一期除交付内容外必须填交付时间（日期或时间窗）。

后端：

- 删除「各工序数量之和 = 总需求量」。
- 方案/报价：工厂承接区间针对整单件数，工价按件（含全部工序）。
- 拆单：`WorkStageSplitter` 按「中标工厂 × 交付期」生成工单，不再按 `processNo` 拆金额。

---

## 阶段 3 · 工厂工单交互

`Stages.vue` 一行一需求、点行展开各期订单：

**需求行：** 需求ID、需求名称、需求详情、工期进度、总计工费、状态。

**展开后每期一行：** 期、约定数量、实交数量、开始时间、截止时间、本期工费、状态、托管、操作。

**时间窗：** 已签约且到达开始时间 → 状态「进行中」，开放上报进度 / 交付；未到开始时间 → 状态「待开启」，不显示这两颗按钮。

拆单：`WorkStageSplitter` 按工厂 × 交付期生成 `work_stage`（`period_no/start/end`）。新工单初始 `WAITING_OPEN`。列表查询时到期自动改为 `IN_PRODUCTION`。旧按工序拆的工单仍按订单分组展示。

发布页每一期（含仅 1 期）必须填开始、截止日期。

关闭连锁后后续期状态为已取消，按钮全部禁用（阶段 6）。

---

## 阶段 4 · 交付 → 质检费 → 质检

现网：交付后直接 `PENDING_INSPECTION`。

改为：

1. 工厂交付，写入实交数量，状态 `PENDING_INSPECT_PAY`。
2. 买家按 `实交数量 × 单价` 支付质检费（转运营账户）。
3. 支付成功 → `PENDING_INSPECTION`，质检员才能填单。
4. 质检员仍不可改实交数。

质量返工：工厂提交返工单后先缴质检费（约定原数量 × 单价），再进入质检。

数量返工：已交部分先按文档托管工费并结算；剩余件数生成新工单；买家为剩余件付质检费。

---

## 阶段 5 · 质检判定与买家决策（核心分支）

保持：无关键超差且 \(Y \ge m\) 才公差合格；数量齐且公差合格才整单合格。

按文档改决策表（替换现网「不能让步仅因数量不齐 / 赔 \(A(m-Y)\)」的部分冲突点）：

| 条件 | 买家可选 | 钱 |
|---|---|---|
| A 齐 + 无关键 + \(Y \ge m\) | 无需决策 | 全额托管本阶段工费 |
| B 不齐 + 无关键 + 良率达标 | 返工补齐 **或** 让步 | 让步：托管已交工费；**扣本阶段全部约定工费的 5%** 赔买家。返工：先托管已交工费；剩余生成返工单 |
| C1 齐 + 无关键 + \(m-5\% \le Y < m\) | 返工 **或** 让步 | 让步按已定 \(A\times Y\) 托管、\(A\times(m-Y)\) 赔付；**若关闭仍扣本阶段 5%** |
| C2 齐 + 无关键 + \(Y < m-5\%\) | 返工 **或** 关闭 | 关闭走连锁赔付 |
| D 不齐 + 无关键 + 良率不达标 | 一次返工；再用尽则关闭 | 关闭走连锁 |
| E 有关键超差 | 返工 **或** 关闭 | 返工后合格则正常托管；再不合格只能关闭 |

返工次数：全程 1 次。分支 B 的返工单再检不合格：只能关闭或让步，不能二次返工。

`InspectRules` / `decideInspect` / 买家 `OrderDetail` 决策弹窗 / `InspectDeliveryRules.vue` 同步改文案与按钮。

---

## 阶段 6 · 关闭连锁

`CLOSE` 时：

1. 计算该厂该需求「本期工费 + 后续未完成期工费」合计 \(T_{\text{left}}\)。
2. 从剩余冻结保证金划 \(5\% \times T_{\text{left}}\) 给买家（不足则不允许只关不赔，或按剩余冻金全划并记缺口——需产品确认；建议与让步一致：不足则禁止关闭并提示运营）。
3. 后续期工单全部 `CLOSED`/`CANCELLED`，不可交付。
4. 本期不交托管工费。

---

## 阶段 7 · 资金与运营

- 质检费流水进运营账户，与工费托管、保证金分开。
- 工厂 1% 佣金仍从托管工钱扣，不占用 5% 保证金。
- 运营端：质检费入账、待付质检费工单列表；关闭连锁审计日志。

---

## 阶段 8 · 联调用例

1. 单期、全合格：买家付质检费 → 检 → 全额托管。
2. 数量不齐、良率达标：让步（已交工费 + 本阶段 5%）；或返工生成剩余件新单。
3. 数量齐、轻微不良：让步 \(A\times Y\) + \(A(m-Y)\)。
4. 数量齐、严重不良：关闭 → 本期+后续 5% 赔付，后续期消失。
5. 关键超差：返工（工厂付质检费，原数量）→ 合格托管 / 不合格关闭连锁。
6. 两期：第一期关闭后第二期按钮不可用且已取消。
7. 未到交付窗：工厂无交付按钮。

---

## 建议实施顺序

1. 模型与发布（工序去数量、分期时间、质检单价）— 不先动质检判定也能编译。
2. 拆单改为厂×期；工厂列表一行一需求。
3. 质检费支付闸门。
4. 判定表 + 让步/返工/关闭金额。
5. 关闭连锁。
6. 规则文案与运营账。

每步停 IDEA 再启后端。不要与「按工序拆工单」旧逻辑并行过久，方案/报价页会一起改。
