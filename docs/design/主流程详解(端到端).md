# 主流程详解（端到端 · 两阶段竞标版）

> 目的：以「真实用户操作」视角，把从注册到整单完成的每一步、每个表单、每个异常走一遍。
> 版本：v2 —— 两阶段竞标（意向期 + 保证金期）+ 主动提醒 + 梯度取消。
> 角色：买家(BUYER)、工厂(FACTORY)、运营(OPERATOR)、质检(INSPECTION)、超级管理员(SUPER_ADMIN)。

---

## 0. 全局约定（先定死，后面不再变）

### 0.1 时间线（三个时间）

| 时间段 | 长度 | 谁定 | 说明 |
|---|---|---|---|
| **意向期** | 买家自定（如 5 天） | 买家发需求时定 | 工厂提交意向、双端可取消 |
| **思考期** | **固定 12 小时** | 系统固定 | 买家决定「继续 or 取消」 |
| **审核期** | **固定 6 小时** | 系统固定 | 仅当买家提出取消时触发，平台审核 |

> 所有时间节点用**定时任务自动流转 + 自动发提醒**，不靠运营手动盯。

### 0.2 两笔钱（意向金 vs 保证金）

| | 意向金 | 保证金 |
|---|---|---|
| 阶段 | 意向期 | 保证金期（买家确认继续后） |
| 金额 | 低、象征性（默认订单预估额 0.1%） | 高（默认订单预估额 1%~3%，可配置） |
| 作用 | 防随便报名 | 防中标后违约 |
| 关联报价 | 意向报价（非绑定，仅参考） | 真实锁定报价（绑定） |
| 记录 | `fund_flow` type=INTENTION | `fund_flow` type=DEPOSIT |

> 两个金额均为**可配置**，本文给默认值。

### 0.3 质量门槛前置（判定「是否有达标工厂」的唯一标准）

买家发需求时**必须写死**质量门槛，事后不得抬高标准。平台据此自动判定：

| 门槛字段 | 说明 |
|---|---|
| AQL | 质检标准 |
| 公差/精度 | 技术规格 |
| 认证要求 | ISO/CE 等 |
| 最低良率 | 买家可接受的最低良率 |
| 最低信用分 | 买家可接受的最低工厂信用分 |

> **关键**：质量门槛是买家**事先声明**的，平台按门槛筛。筛不到 = 流拍（可取消）；筛得到 = 买家自己放弃（不可退）。

### 0.4 报价区间（解决「凑不齐/凑超」）

工厂报价「可承接量」是**区间**，不是固定数：

| 字段 | 说明 |
|---|---|
| `min_qty` | 最小起订量（低于不接） |
| `max_qty` | 最大可承接量（产能上限） |

> 平台分配时，每家工厂拿到的量在 `[min_qty, max_qty]` 之间，凑齐总需求。

## 阶段 0：注册与登录

### 0.1 谁先进系统

- **买家/工厂**：自主注册（client-web）。
- **运营/质检**：超级管理员创建并发放账号（admin-web）。
- **超级管理员**：系统内置唯一。

### 0.2 注册表单（买家/工厂）

| 字段 | 类型 | 必填 | 校验 | 落库 |
|---|---|---|---|---|
| 手机号 | text | ✅ | 11 位、未注册 | `user.phone` |
| 密码 | password | ✅ | 8~20 位含字母数字 | `user.password`(BCrypt) |
| 确认密码 | password | ✅ | 一致 | 不落库 |
| 企业名称 | text | ✅ | ≤128 字 | `enterprise.name` |
| 统一社会信用代码 | text | ✅ | 18 位、唯一 | `enterprise.credit_code` |
| 企业类型 | radio | ✅ | 买家/工厂 | `enterprise.type` |
| 联系人 | text | ✅ | 非空 | `enterprise.contact_name`(脱敏) |
| 营业执照 | 图片 | ✅ | ≤5MB | `attachment`(CERT) |

**异常**：手机号已注册 / 信用代码重复 / 营业执照超限 / 密码太弱 → 拒绝并提示。

### 0.3 登录

| 字段 | 必填 | 说明 |
|---|---|---|
| 手机号 | ✅ | |
| 密码 | ✅ | |
| 验证码 | 条件 | 连续失败 3 次出现 |

**异常**：账号密码错误（统一提示）/ 连续失败 5 次锁 30 分钟 / 账号禁用 / 登录过期返回 401。

## 阶段 1：工厂完善能力档案与产能（报价前提）

工厂不填完，**不能参与竞标**。

### 1.1 能力档案表单

| 字段 | 必填 | 说明 |
|---|---|---|
| 设备清单 | ✅ | 每台：设备名/型号/精度/数量 |
| 可加工材料 | ✅ | 多选 |
| 工艺能力 | ✅ | 多选+文本 |
| 历史合格率 | ✅ | 0~100% |
| 认证证书 | ❌ | 存 attachment(CERT) |

### 1.2 产能录入

| 字段 | 必填 | 说明 |
|---|---|---|
| 各工序可用产能(件/天) | ✅ | 用于「产能匹配」过滤器 |

## 阶段 2：买家发布需求（含质量门槛 + 意向期）

### 2.1 需求表单

| 分组 | 字段 | 必填 | 说明 |
|---|---|---|---|
| 基础 | 需求标题 | ✅ | |
| | 产品名称 | ✅ | |
| | 产品类别 | ✅ | |
| | 数量 | ✅ | >0 整数 |
| 技术规格 | 材料 | ✅ | |
| | 公差/精度 | ✅ | |
| | 表面处理 | ❌ | |
| | AQL | ✅ | **质量门槛** |
| | 认证要求 | ❌ | **质量门槛** |
| 质量门槛 | 最低良率 | ✅ | 如 ≥97% |
| | 最低信用分 | ✅ | 如 ≥80 |
| 交期 | 硬交期 | ✅ | 晚于今天 |
| | 弹性交期 | ❌ | |
| 工序 | 是否多工序 | ✅ | |
| | 工序列表 | 条件 | 每道：工序名/数量/特殊要求 |
| 交付 | 交付地址 | ✅ | |
| | 包装要求 | ❌ | |
| 意向期 | 意向期天数 | ✅ | 买家自定（如 5 天） |
| 偏好 | 成本/工期/质量权重 | ✅ | 三者之和=1 |
| 其他 | 备注 | ❌ | |
| 图纸 | 图纸/文档 | ✅ | 存 attachment(DEMAND) |

### 2.2 提交

1. 后端校验必填 + 质量门槛字段。
2. 写 `demand` + `process` + `attachment`。
3. 状态 DRAFT → 待审核。

---

## 阶段 3：运营审核需求

- 运营审核真实性/合理性 → **通过** / **驳回**。
- 通过 → 需求进入「意向期」，`demand.status=PUBLISHED`，意向期开始倒计时。
- 驳回 → 退回买家修改或 CANCELLED。

---

## 阶段 4：意向期（工厂交意向金 + 意向信息）

### 4.1 工厂提交意向（第一阶段，非绑定）

| 字段 | 必填 | 说明 |
|---|---|---|
| 意向工位/工序 | ✅ | 选一个工序 |
| 设备信息 | ✅ | 从能力档案带出 |
| 产能 | ✅ | 该工位可用产能 |
| 能力证明 | ✅ | 认证/良率/历史 |
| 想承接量区间 | ✅ | `min_qty`~`max_qty` |
| 意向报价（非绑定） | ✅ | 仅参考，不锁定 |
| 报价有效期 | ✅ | 如「本报价 7 天内有效」 |
| 确认冻结意向金 | ✅ | 勾选 |

**系统处理**：
1. 冻结意向金 → `fund_flow`(type=INTENTION, direction=FREEZE)。
2. `quotation.status=INTENTION`，`intention_status=FROZEN`。
3. 记审计。

### 4.2 取消规则（意向期内）

| 谁 | 能否取消 | 处理 |
|---|---|---|
| **工厂** | ✅ 可取消 | 全额退意向金，不扣 |
| **买家** | ✅ 可取消 | 给原因 → 平台审核 → 通过则全额退双端意向金 |

---

## 阶段 5：意向期结束前的主动提醒

意向期即将结束（如剩 24h），系统自动判定并提醒：

### 5.1 产能不足 → 主动问买家

> 若所有工厂 `max_qty` 之和 < 订单总量（凑不齐）→ 给买家发提醒：「当前总产能无法满足需求，是否取消订单？」

买家可选：取消（走取消流程，退双端意向金）或 继续（接受分批/减量）。

### 5.2 工厂过多 → 提醒工厂

> 若产能充足、但参与工厂过多 → 给工厂发提醒：「已有多人竞选该工位，是否继续参加？」

**注意**：只发「已有人参与」信号，**不泄露具体数量、不泄露竞对身份**（防合谋围标）。

---

## 阶段 6：思考期（固定 12 小时，买家）

意向期结束 → 进入 12 小时思考期，买家做决定。

### 6.1 买家三种取消情形（自动判定，不主观）

| 情形 | 判定依据 | 结果 |
|---|---|---|
| ① 无达标工厂 | 按买家事先声明的质量门槛筛，筛不到 | ✅ 自动允许取消，退双端意向金 |
| ② 产能不足 | `Σ max_qty < 订单总量` | ✅ 自动允许取消，退双端意向金 |
| ③ 都满足还要取消 | 有达标工厂且产能够，买家仍取消 | ⚠️ 需理由+证明，进审核期 |

### 6.2 买家确认继续

买家在思考期点「继续」→ 跳过审核，直接进入保证金阶段。

---

## 阶段 7：审核期（固定 6 小时，平台）

> 仅当买家在思考期提出「情形③取消」时触发。

- 平台 6 小时内审核买家的「理由 + 证明」。
- **审核通过** → 允许取消，退双端意向金。
- **审核不通过** → 判定买家反悔，**扣买家部分意向金（默认 50%）赔给工厂**，其余退还，订单继续进入保证金阶段。

> 规则越机械越少纠纷：①② 客观判定，③ 严格把关。平台不得从「扣的钱」里分成（扣的钱全赔工厂）。

---

## 阶段 8：保证金阶段（工厂交保证金 + 真实锁定报价）

买家确认继续、平台审核通过后，进入第二阶段。

### 8.1 工厂提交锁定报价（绑定）

| 字段 | 必填 | 说明 |
|---|---|---|
| 工位/工序 | ✅ | |
| 真实报价价格 | ✅ | `quotation.price`（绑定） |
| 良率承诺 | ✅ | `yield_rate` |
| 总工期 | ✅ | `promised_days` |
| 承接量区间 | ✅ | `min_qty`~`max_qty` |
| 分阶段工期曲线 | ✅ | 每阶段【阶段号/交付数量/日期】 |
| 确认冻结保证金 | ✅ | |

**系统处理**：
1. 冻结保证金 → `fund_flow`(DEPOSIT, FREEZE)，`quotation.deposit_status=FROZEN`。
2. `quotation.status`：INTENTION → **LOCKED**。
3. 校验产能匹配 + 工期不超硬交期。

### 8.2 工厂取消（保证金期）

| 情形 | 处理 |
|---|---|
| 交保证金后取消 | **扣保证金**，信用分下调 |
| 中标后弃标/违约 | **没收保证金**，信用分重罚 |

---

## 阶段 9：生成建议方案

保证金阶段截止 → 平台算法生成方案。

1. **过滤器**：剔除能力不匹配、产能不匹配的报价。
2. **评分器**：`综合评分 = w1·成本 + w2·工期 + w3·质量 + w4·信用`。
3. **枚举组合 + 整数分配**：每工位选厂，按 `min_qty~max_qty` 区间贪心凑齐总需求。
4. **帕累托最优 3 个** → 方案 A/B/C。
5. 写 `solution`(source=SUGGESTED)。
6. `demand.status` → SOLUTION_GENERATED。

**异常**：某工位无人报价 / 全部被过滤 → 流拍，退双端，`demand.status=FLOW_FAILED`。

---

## 阶段 10：买家查看/编辑方案 + 确认

- 买家看 A/B/C（工厂显示代号+信用分，联系方式脱敏）。
- 买家可**换厂**（某工序换另一候选厂），但**不能改报价内容**（价格/工期/质量是工厂的，买家无权改）。
- 编辑留痕 → `solution.edited_fields_json`。
- 确认 → 生成最终方案 + 订单。

**异常**：换的厂产能不足/不达标 → 禁止换。

---

## 阶段 11：签合同（锁版）

- 生成合同（抽样方案 + 责任条款）。
- 买家 + 各中标工厂分别确认签约。
- `contract.hash` 存证，需求锁版。
- `order.status` → CONTRACTED。

---

## 阶段 12：拆工单 + 生产交付

- 按最终方案拆 `work_stage`（每工序一个，分配给中标工厂）。
- 工厂报工（**阶段交付时一次报工**，简化粒度）。
- 交付 → `work_stage.status` → PENDING_INSPECTION。

**异常**：延期 → 扣保证金 + 信用下调；交付数量不足 → 不能进质检。

---

## 阶段 13：质检（第三方，本期运营代录）

| 字段 | 必填 | 说明 |
|---|---|---|
| 工单 | ✅ | |
| 抽检数量 | ✅ | 按合同抽样方案 |
| 不合格数 | ✅ | |
| 结果 | ✅ | 合格/不合格 |
| 报告附件 | ❌ | attachment(INSPECTION) |

- 合格 → PASS；不合格 → FAIL（返工/报废+违约金）。
- `inspection.hash` 存证。
- **质检与工序对应**：每个工单（工序）完成后一次质检。

---

## 阶段 14：资金释放 + 佣金

- 质检 PASS → 释放保证金 + 放款（状态机触发，幂等）。
- 佣金 = 订单总额 × 费率（一次计），按工厂占比分摊。

---

## 阶段 15：整体验收 + 信用结算

- 全部工单质检通过 → 买家终验 → 完成。
- 信用结算（履约加分/违约扣分）+ 互评。

---

## 附 A：全流程状态机

```
demand:  DRAFT → PUBLISHED(意向期) → THINKING(思考期) → REVIEWING(审核期)
         → LOCKING(保证金期) → SOLUTION_GENERATED → SOLUTION_SELECTED
         → CONTRACTED → IN_PRODUCTION → COMPLETED
         分支：CANCELLED / FLOW_FAILED

quotation: INTENTION(意向) → LOCKED(锁定) → WIN / LOSE / INVALID
           intention_status: NONE → FROZEN → RELEASED / FORFEITED
           deposit_status:   NONE → FROZEN → RELEASED / FORFEITED

order:     CREATED → CONTRACTED → IN_PRODUCTION → DELIVERED → ACCEPTED → COMPLETED
           分支：CANCELLED / DISPUTE

work_stage: PENDING → IN_PRODUCTION → PENDING_INSPECTION → INSPECTING → PASS/FAIL → COMPLETED
```

## 附 B：时间线一张图

```
发布需求(质量门槛+意向期天数)
  └─ 意向期(买家定N天)：工厂交意向金+意向报价；双端可取消
       └─ 结束前提醒：产能不足问买家 / 工厂过多提醒工厂
  └─ 思考期(固定12h)：买家继续 or 取消(①②自动退/③进审核)
       └─ 审核期(固定6h)：平台审③，不通过扣买家意向金
  └─ 保证金期：工厂交保证金+锁定报价；取消扣保证金
  └─ 生成方案 → 买家选/编辑 → 签约 → 生产 → 质检 → 放款 → 完成
```

## 附 C：取消规则总表

| 角色 | 阶段 | 能否取消 | 钱怎么处理 |
|---|---|---|---|
| 工厂 | 意向期 | ✅ | 全额退意向金 |
| 工厂 | 保证金期 | ❌ | 扣保证金 |
| 工厂 | 中标后 | ❌ | 没收保证金 |
| 买家 | 意向期 | ✅(给原因) | 平台审核通过→全退双端 |
| 买家 | 思考期①② | ✅ | 自动退双端意向金 |
| 买家 | 思考期③ | ⚠️ | 审核通过退；不通过扣买家50%意向金赔工厂 |
| 买家 | 签约后 | ❌ | 违约，诚意不退，赔工厂 |
